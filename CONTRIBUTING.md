# Contributing

Start with [methodology](METHODOLOGY.md), [results](RESULTS.md) and [limitations](LIMITATIONS.md). Contributions should improve the evidence chain or make it easier to inspect.

Use a GitHub issue for a scientific discrepancy, dataset suggestion or reproducibility failure. Include the release/commit, exact file/row, phenotype and cohort, source DOI/accession, expected versus observed result, and whether the source is independent of existing evidence. Do not include credentials, participant records or private correspondence. Report those privately under [SECURITY.md](SECURITY.md).

For pull requests:

1. Preserve historical results; add dated corrections and a current output rather than silently replacing scientific claims.
2. Supply provenance, source terms and allele/build definitions with new data. Public access alone is not a licence. Never upload controlled-access records.
3. Keep educational attainment, clinical traits and mathematical proxies separate from direct cognition. Collapse shared cohorts and evidence classes before counting support.
4. Document changes to frozen thresholds/seeds as amendments, including whether outcomes were already viewed. Keep competing gene hypotheses and negative findings.
5. Run the [smoke check and relevant offline tests](REPRODUCIBILITY.md). Report omitted tests and missing inputs. Do not run large analyses or service calls merely to refresh presentation.
6. Declare AI assistance, automated transformations and the extent of human/source verification.

Code contributions are accepted under MIT; original documentation under CC BY 4.0. Contributors must identify any third-party terms separately. A contribution must not imply that genetic association, model prediction, tractability or loss of function establishes enhancement efficacy or safety.
